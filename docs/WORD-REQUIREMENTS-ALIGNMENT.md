# 教师帮 V1.0 立项书需求对齐说明

基线文档：`教师帮_项目立项书_V1.0.docx`（2026-07-31）

## 1. 与最初需求相比，立项书扩大了什么

最初需求的产品核心是“上传教材章节 → AI 生成详细教案 → 教师反复提出修改 → 满意后导出”，并配套用户注册、会员优惠、模型 API 管理、一键部署以及未来训练素材沉淀。

立项书保留了上述核心，并将产品进一步升级为“教案—知识点—组卷一体化平台”：

1. 教案不再只是最终文件，还要自动沉淀为稳定的知识点结构。
2. 习题不再只是教案附件，而要进入独立题库，支持题源、难度、认知层级、教学环节、推荐分数、去重、排序和试卷导出。
3. 数据资产从“最终教案训练样本”扩展为“教案—知识点—题目关系图谱 + 教师选题行为”。
4. 新增备课组评审、学校与区域客户、多角色权限及 C/B/G 三类商业模式。
5. 教材读取从外部多模态模型直读，进一步要求演进为本地 OCR、版面分块、公式 LaTeX 和人工确认。
6. 产品首发学科建议聚焦初中数学；当前系统继续支持多学科，演示数据后续增加初中数学主场景。

## 2. 当前版本已经覆盖的内容

- 用户注册、登录、签名 HttpOnly 会话与免费额度。
- JPG、PNG、WEBP、PDF 教材上传与 AI 结构化教案生成。
- 逐分钟课堂流程、教师讲解话术、学生情绪与参与设计、分层策略、板书、作业以及至少 10 道含答案解析的习题。
- 用自然语言反复修改教案，生成状态与错误反馈。
- DOC、打印/PDF、JSON 导出。
- 管理员模型通道、优先级和加密 API Key 存储。
- 服务端权威会员套餐、限时直减、管理员套餐维护和教师端真实结算界面。
- 手机号/邮箱验证码注册、登录与找回密码，SMTP 域名邮箱及阿里云/腾讯云短信配置。
- 可选管理员登录验证码：首次仍用账号密码，管理员主动开启后才在后续登录要求“验证码”。
- 微信支付 Native API v3 与支付宝电脑网站支付的下单、通知验签、金额核对、订单幂等及会员/点数发放闭环。
- 训练候选的明确授权、权利确认、脱敏、去重、待审核和撤回流程。
- Docker Compose + Caddy 一键部署，HTTPS 自动申请和续期。

## 3. 本轮按立项书补齐的 MVP 闭环

### 教案 → 知识点

- 新增教师端“教学认知图谱”。
- 从教案目标、重难点和习题标注提取知识点。
- 展示教案、知识点、题目三类节点及“教授”“考察于”关系。
- 展示认知层级、适用教学环节、关系置信度、题目标注率和待仲裁冲突。
- 新增受登录保护的 `/api/workflow/knowledge-map` 接口及独立 Schema。

### 知识点 → 智能组卷

- 新增教师端“智能组卷”。
- 支持知识点、难度、题型筛选，加入/移除题目和顺序调整。
- 支持易 → 中 → 难排序、题型交替提示、重复检测、知识点覆盖统计。
- 使用立项书提出的 `0.4 × 相关性 + 0.3 × 质量度 + 0.2 × 教师偏好 + 0.1 × 多样性` 作为可解释评分结构。
- 可预览学生卷，分别导出学生版和答案版。
- 明确标注当前是规则推荐，不冒充已完成的 BGE/pgvector 向量推荐。
- 新增受登录保护的 `/api/workflow/papers/recommend` 接口及独立题目/试卷 Schema。

### 备课组协同

- 新增备课组工作台、共享教案、评审队列、版本标识、批注、退回和通过交互。
- 当前为交互式 MVP；正式多租户、多人同步和细粒度权限待 PostgreSQL 数据层接入。

### 管理后台与可读性

- 教案编辑器按正常教师端阅读尺度放大正文、课堂表格、侧栏和 AI 对话。
- 管理后台新增安全的一次性首次初始化流程；已有管理员时仍只显示登录。
- 生产环境继续由一键安装脚本预置管理员，不使用默认账号或默认密码。

### 账号、通信与支付

- 新用户在生产环境必须通过绑定手机号或邮箱验证码注册，支持验证码登录与密码找回；验证码单次使用、短时有效并有限流。
- 管理后台可配置 SMTP TLS/STARTTLS、阿里云短信或腾讯云短信，密钥仅在服务端加密保存；未配置或投递失败时不会伪造“发送成功”。
- 管理员可维护服务端权威套餐、点数、有效期、上下架以及有明确起止时间的限时优惠。
- 教师结算使用当前绑定账号验证码；浏览器不能决定成交价或权益。微信/支付宝通知验签成功后，系统按订单号幂等发放会员和点数。
- 当前不会模拟主动查单、退款、发票或风控结果；这些能力必须在真实商户环境联调后再开放。

## 4. 有意保留的技术取舍

立项书中的 Vue 3、FastAPI、PostgreSQL、Neo4j、pgvector、Redis 是目标技术建议，不是需要立即推翻当前项目的功能需求。

当前保留已经通过安全与集成测试的 React + Node 产品层，原因是它已经具备用户、AI、额度、加密模型通道、训练治理和一键部署闭环。下一阶段把以下重计算能力拆成 Python 服务即可：

- PaddleOCR / PP-DocLayout 教材结构化；
- Embedding 与向量召回；
- 推荐排序与题目相似度检测；
- 微调、蒸馏与评测任务。

数据规模扩大后，再把单机 JSON 数据迁移为 PostgreSQL + pgvector + Redis；只有图谱查询规模证明有必要时再引入 Neo4j。

## 5. 下一阶段必须继续完成

1. Tiptap + KaTeX 富文本编辑、图片/表格/公式和真实撤销重做。
2. 教案不可变版本、差异对比、恢复、送审与服务端评审记录。
3. 正式 `.docx` 导出、装订线、誊分栏、学生卷和答案卷排版模板。
4. PaddleOCR 本地服务、版面块确认页、低置信内容高亮和原图生命周期策略。
5. 授权题库、Excel/Word 批量导入、题源审核和 95% 相似去重。
6. PostgreSQL 多租户、学校/区域组织、角色权限、教师行为日志与错题回流。
7. 微信/支付宝真实商户联调、主动查单与日终对账、关单退款、发票、合同和 C/B/G 组织套餐。

## 6. 部署原则保持不变

正式发布仍采用一键安装：输入域名、管理员账号和管理员密码后启动 Docker Compose，由 Caddy 自动申请并续期 HTTPS 证书。Cloudflare 首次签发证书时使用 DNS only，证书签发成功后可切换为 Proxied，并启用 Full (strict)。GitHub 仓库和公开安装命令在产品整改稳定后再发布。
