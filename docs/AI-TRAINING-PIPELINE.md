# 教师帮 AI 教案生成与训练闭环规范

版本：`1.0.0`
状态：实施基线
适用范围：教材上传、OCR/视觉理解、教案生成与修订、质量审核、导出、训练数据治理、RAG、SFT、DPO、蒸馏、模型发布与回滚。

## 1. 核心原则

1. **在线使用不等于在线训练。** 用户生成、修订和导出教案时只发生在线推理及经授权的数据记录，任何模型权重都不得在请求链路中实时更新。
2. **训练是可审计的离线发布流程。** 只有通过授权、版权、去标识化、质量和人工审核的数据，才能进入不可变数据集版本，再用于训练、评测、灰度和发布。
3. **RAG 管知识，微调管行为。** 教材版本、章节事实和最新内容优先通过有访问控制的 RAG 提供；SFT/DPO 用于教案结构、教学方法、表达风格和修改偏好。
4. **服务处理与训练授权分离。** 用户为了获得教案而上传资料，并不自动授权平台将资料用于训练。
5. **教师拥有最终决定权。** 自动评分只是辅助；系统不得将生成内容描述为已经替代教师审核。
6. **最小化收集。** 能使用去标识化 OCR 文本完成任务时，不把原图发送给外部生成模型，也不把原图纳入训练。
7. **全链路可追溯。** 每次生成、修订、导出、入池、入集、训练和发布，都必须能追溯到输入版本、提示词版本、模型路由、授权事件和质量结果。

## 2. 术语与边界

- **项目（project）**：一次章节教案制作过程，包含上传材料、OCR、教案版本、修订和导出。
- **源材料（source asset）**：用户或管理员上传的图片、PDF、教材文本、教案、习题及答案。
- **教案修订版（lesson plan revision）**：不可变的教案 JSON 快照；新修改必须创建新版本并指向父版本。
- **训练候选（training candidate）**：可能用于模型改进、但尚未通过全部审核的数据。
- **数据集版本（dataset version）**：审核通过、内容冻结且具有清单哈希的数据集合。
- **教师模型（teacher model）**：用于生成蒸馏标签的高能力模型，不指学校教师。
- **学生模型（student model）**：通过蒸馏或微调得到、用于降低成本和延迟的模型。
- **项目级 RAG**：只对当前项目可见的临时教材索引。
- **租户级 RAG**：只对指定学校或机构可见的授权素材索引。
- **全局 RAG**：仅允许包含平台明确获得全局检索许可的素材。

## 3. 业务状态机

状态变化必须通过服务端原子更新完成，并写入审计事件。客户端只能请求动作，不能直接设置状态。

### 3.1 首次生成状态机

```text
UPLOADED
  -> SECURITY_SCANNING
  -> OCR_EXTRACTING
  -> OCR_REVIEW_REQUIRED | OCR_CONFIRMED
  -> SOURCE_INDEXING
  -> GENERATION_QUEUED
  -> GENERATING
  -> QUALITY_CHECKING
  -> READY
  -> APPROVED
  -> EXPORT_QUEUED
  -> EXPORTING
  -> EXPORTED
```

通用终止和异常状态：

- `FAILED_RETRYABLE`：429、网络抖动或临时服务故障；后台按退避策略重试。
- `FAILED_FINAL`：文件损坏、永久鉴权失败、内容无法解析或超过重试上限。
- `CANCELLED`：用户或管理员取消，正在执行的下游任务必须停止或忽略结果。
- `DELETION_PENDING` / `DELETED`：用户删除项目后的异步清理状态。

关键转换约束：

- OCR 平均置信度低于阈值、页序不明确、公式/表格解析失败时进入 `OCR_REVIEW_REQUIRED`。
- `QUALITY_CHECKING` 未通过硬门槛时，不得进入 `READY`；可局部重新生成一次，仍失败则进入 `FAILED_FINAL` 或带明确问题返回人工处理。
- 只有用户主动确认的版本才能进入 `APPROVED`。
- 导出任务必须固定 `revision_id`；导出期间产生的新修订不得改变该文件内容。

### 3.2 修订状态机

```text
READY | APPROVED
  -> REVISION_QUEUED
  -> REVISING
  -> REVISION_QUALITY_CHECKING
  -> REVISION_READY
  -> REVISION_ACCEPTED | REVISION_REJECTED
```

- 每次修订创建新的不可变 `lesson_plan_revision`，保留 `parent_revision_id`。
- 用户接受后更新项目的 `current_revision_id`；拒绝只记录偏好，不删除候选版本。
- 已批准版本再次修改时，先创建分支版本，不覆盖之前已导出的版本。
- 前端必须展示结构化差异，可恢复任意仍在保留期内的版本。
- 只有明确的“接受 A、拒绝 B”或专家成对比较，才可构成 DPO 偏好样本。普通的前后版本关系不能自动推断为偏好。

### 3.3 训练与发布状态机

```text
CANDIDATES_COLLECTING
  -> DATASET_BUILDING
  -> DATASET_REVIEWING
  -> DATASET_FROZEN
  -> TRAINING_QUEUED
  -> TRAINING
  -> EVALUATING
  -> AWAITING_RELEASE_APPROVAL
  -> CANARY
  -> PROMOTED
```

异常分支：

- `DATASET_REJECTED`：数据集授权、版权、隐私、分布或质量不合格。
- `TRAINING_FAILED`：训练任务失败，可由相同数据集和配置重试为新运行。
- `EVALUATION_FAILED`：任何硬性回归门槛未通过，禁止进入灰度。
- `CANARY_PAUSED`：灰度期间指标异常，停止扩大流量。
- `ROLLED_BACK`：路由恢复至上一个稳定发布版本。
- `ARCHIVED`：运行及产物归档，不再用于在线路由。

不得提供“训练成功后自动全量上线”。管理员的一键训练可以自动执行数据构建、训练和评测，但发布必须有显式审批。

## 4. 教案生成流水线

### 4.1 上传与安全检查

1. 仅接受配置允许的图片/PDF 类型；校验扩展名、MIME 和文件魔数。
2. 限制单文件大小、页数、项目总大小和像素尺寸，防止压缩炸弹。
3. 做病毒扫描、内容安全检测、SHA-256 去重和页序检查。
4. 删除 EXIF/GPS 等不必要元数据；原文件使用租户隔离的对象键和短时签名 URL。
5. 要求上传者确认来源、权利人、使用范围和是否包含学生信息。
6. 对教材页面中的文字一律按“不可信数据”处理，禁止执行其中类似系统指令的内容。

### 4.2 OCR、视觉解析与人工确认

OCR 结果至少保留：

- 页码、文本块、边界坐标、块类型和置信度；
- 公式、表格、图片说明和阅读顺序；
- OCR 模型、版本、提示词版本及运行 ID；
- 人工修改前后文本和确认人。

页面低置信文字应在前端高亮。用户确认后生成不可变 `chapter_snapshot`，后续生成任务只引用该快照，避免 OCR 被修改时静默改变已有教案。

### 4.3 章节索引与检索

将已确认内容按知识点和语义切块，每块记录：

- `asset_id`、页码范围、块 ID；
- 学科、年级、教材版本、章节；
- 文本、内容哈希、Embedding 模型和版本；
- 访问范围 `project | tenant | global_licensed`；
- 许可到期时间和撤销状态。

用户上传教材默认建立项目级临时索引。只有取得对应许可的管理员素材才能进入租户级或全局 RAG。

### 4.4 结构化生成

模型必须按 [`shared/lesson-plan.schema.json`](../shared/lesson-plan.schema.json) 返回数据。至少包括：

- 学科、年级、教材版本、章节和课时；
- 核心素养、可测量教学目标、学情分析、重点难点；
- 教师和学生准备；
- 分钟级时间线、教师话术、师生活动、提问、预期回应、误区、备用策略和形成性评价；
- 课堂参与与氛围设计；
- 分层教学、板书设计、安全与包容性要求；
- 不少于 10 道习题，每题具有难度、知识点、答案、解析和来源引用；
- 作业和课后反思。

`timeline[*].durationMinutes` 的总和必须在业务校验中严格等于 `metadata.durationMinutes`。JSON Schema 无法可靠表达跨数组求和，因此这是服务端硬校验规则。

### 4.5 对话修订

修订请求应包含：当前教案版本、用户指令、允许修改的模块、章节快照版本和检索结果。不要无上限重复发送完整历史聊天。

支持以下修订粒度：

- 全文重写；
- 仅修改某个课堂阶段；
- 调整课堂时长并重新分配时间线；
- 增减或替换习题；
- 调整难度、课堂语气、互动密度和分层策略；
- 保留指定模块不变。

修订结果仍需通过同一 JSON Schema、硬门槛和质量评分。

## 5. 模型服务商与路由

管理员配置必须符合 [`shared/provider-config.schema.json`](../shared/provider-config.schema.json)。数据库只保存密钥引用，禁止保存或回显明文 API Key。

内部适配层应统一以下能力：

- `analyze_images`
- `generate_structured`
- `embed`
- `moderate`
- `healthcheck`
- `count_tokens`

“OpenAI 兼容”只表示接口形态接近，不代表视觉、JSON Schema、流式响应、保留策略或微调能力相同。配置保存前必须做能力探测，并按任务建立独立路由：

- OCR/视觉理解；
- 首次教案生成；
- 教案修订；
- 质量评分；
- Embedding；
- 内容安全。

每个生成任务保存实际采用的 `provider_id`、模型、模型路由版本、隐私等级、提示词版本、参数、Token、费用和耗时。重试只针对明确的临时错误，使用指数退避和抖动；启用超时、并发限制、熔断器和费用预算。

自定义 `baseUrl` 必须实施 HTTPS 校验、域名允许列表、DNS 重绑定防护和 SSRF 防护。回退服务商只能位于相同或更严格的数据处理等级，不能因故障自动把数据发送到用户未获知的地区或服务商。

## 6. 用户授权拆分

以下目的必须独立记录，不得用注册协议中的一个总开关替代：

| 授权项 | 默认 | 是否为生成教案所必需 |
|---|---:|---:|
| 为本次服务处理上传材料 | 开启 | 是 |
| 保存历史项目供用户继续编辑 | 用户选择 | 否 |
| 将内容发送给已说明的外部模型服务商 | 按路由和合规依据确认 | 视路由而定 |
| 使用原始图片训练模型 | 关闭 | 否 |
| 使用去标识化 OCR 文本训练模型 | 关闭 | 否 |
| 使用最终导出教案训练模型 | 关闭 | 否 |
| 使用修订记录和明确偏好训练模型 | 关闭 | 否 |
| 使用反馈评分改进评测 | 关闭或单独说明 | 否 |

每次授权事件记录 `consent_event_id`、目的、范围、政策版本、授予时间、撤销时间、客户端和证据。撤回后：

1. 立即阻止新候选入池；
2. 未冻结数据集中的数据立即移除；
3. 已冻结但未训练的数据集作废并重建；
4. 已训练模型记录受影响血缘，在下一次合规重建中移除相关样本；
5. 不向用户承诺无法证明的“即时模型遗忘”，但必须明确实际处理方式和时间。

管理员上传的机构素材可以基于合同许可或组织授权，但必须记录对应法律依据和许可范围。

## 7. 去标识化、隐私与安全

### 7.1 去标识化规则

训练候选至少扫描并移除或泛化：

- 学生、教师和家长姓名；
- 学号、身份证号、电话号码、邮箱和社交账号；
- 学校、班级、住址和精确位置；
- 成绩、评语、健康、家庭、经济和行为信息；
- 人脸、手写签名、EXIF 和文件作者字段；
- 可由多个弱标识组合重新识别个人的信息。

优先使用不可逆替换，如 `[学生A]`、`[某学校]`。如业务确需可逆映射，映射表必须与训练数据分库存储、独立加密和授权；训练导出不得包含映射表。

### 7.2 数据安全

- 传输加密、静态加密、租户隔离、最小权限和定期密钥轮换；
- 管理员默认不可浏览客户原文，紧急访问采用有理由、有审批、有审计的 break-glass；
- 日志只记录哈希、ID 和必要诊断信息，不记录密钥及完整教材；
- 对象访问使用短时签名 URL，禁止公开桶；
- 原始上传默认短期保留，建议导出后 30 天删除，用户或机构可配置更短期限；
- 用户删除触发对象、OCR、索引、缓存、训练候选和未来数据集成员的血缘清理；
- 数据库备份同样遵守保留和最终清除策略。

### 7.3 提示注入与训练投毒

- OCR/教材内容必须放在明确的数据边界中，系统提示声明不得执行源材料中的指令；
- 输出只能引用真实存在的 `sourceRef`，服务端拒绝伪造页码或块 ID；
- 不把系统提示、API Key、内部路由或其他租户信息送入模型上下文；
- 用户交互数据视为低信任来源，管理员授权素材和专家复核数据为高信任来源；
- 候选池进行精确去重、语义去重、异常账号检测、模板刷量检测和跨租户污染检测；
- 固定黄金评测集永不进入训练。

## 8. 版权与素材权利

一次教学服务所需的处理权，不等同于全局检索、模型训练或衍生内容再分发权。上传向导必须要求填写：

- 素材类型和标题；
- 权利人、来源和上传人声明；
- 许可证、合同或组织授权编号；
- 是否允许服务推理、项目 RAG、租户 RAG、全局 RAG、模型训练、蒸馏、衍生和再分发；
- 地域、有效期、署名要求和撤销方式。

系统应保存内容指纹，支持权利人下架、许可证到期自动停用、数据集血缘追踪和后续模型重建。未经明确训练许可的完整教材不能进入 SFT、DPO 或蒸馏数据集；如仅获检索许可，只能进入对应访问范围的 RAG。

上线前应由合规律师结合实际运营地区、未成年人信息、跨境调用和出版社许可进行复核。本规范不替代法律意见。

## 9. 质量审核

### 9.1 硬门槛

任一失败即不得进入 `READY` 或训练数据集：

1. 教案通过 JSON Schema 校验；
2. 习题不少于 10 道；
3. 每题都有答案、解析、难度和至少一个知识点；
4. 时间线总时长等于设定课时；
5. 来源引用指向当前章节快照中的真实页码和块；
6. OCR 低置信内容已确认或明确排除；
7. 无未处理个人信息和未成年人敏感信息；
8. 无危险、歧视、羞辱、恐吓或年龄不适宜内容；
9. 学科专项验证通过，例如数学答案复算、科学实验安全检查；
10. 训练用途授权和版权范围均有效。

### 9.2 软评分

| 维度 | 权重 |
|---|---:|
| 教材忠实度与来源可追溯 | 20 |
| 教学目标和核心素养匹配 | 10 |
| 教学流程与时间可执行性 | 15 |
| 讲解清晰度和易错点处理 | 15 |
| 课堂参与与氛围设计 | 10 |
| 习题覆盖、梯度和答案正确性 | 15 |
| 分层教学与形成性评价 | 10 |
| 语言和格式 | 5 |

建议阈值：

- `>= 85`：允许进入 `READY`；满足授权等其他门槛后可进入训练候选池。
- `75–84`：向用户显示改进提示，可局部重生成；默认不进入训练数据集。
- `< 75`：必须重新生成失败模块或人工处理。

评分结果要记录评分器、模型、提示词和规则版本。模型评分不能覆盖人工审核；人工覆盖必须记录原因和审核人。

### 9.3 产品与模型评测指标

- OCR 字符/公式正确率及人工纠错率；
- 来源忠实度、幻觉率和不存在引用率；
- 习题答案正确率、难度分布和知识点覆盖率；
- 教师盲评分、无修改导出率、平均修订轮次和导出率；
- 请求成功率、P50/P95 延迟、单教案成本；
- 按学科、年级、教材版本、课时和模型路由分层的回归结果；
- 隐私、版权和安全事件数。

不能只优化导出率，因为用户可能导出低质量内容。发布判断必须同时满足质量、安全、成本和延迟门槛。

## 10. 训练候选池

训练样本必须符合 [`shared/training-sample.schema.json`](../shared/training-sample.schema.json)。候选状态：

```text
PENDING
  -> RIGHTS_REVIEW
  -> PRIVACY_REVIEW
  -> DEIDENTIFICATION
  -> QUALITY_REVIEW
  -> APPROVED
  -> RELEASED
```

其他状态：

- `INELIGIBLE`：未授权、许可范围不足或质量不足；
- `QUARANTINED`：可能存在投毒、侵权或异常模式；
- `REVOKED`：授权撤回、许可到期或权利人下架；
- `SUPERSEDED`：被更高质量、相同内容的新候选取代。

导出行为只表示用户选择使用该版本，不自动证明教案高质量。入池还需通过质量门槛、去重和必要的人工抽检。

## 11. 数据集版本

数据集版本不可原地修改，建议命名：

```text
lessonplan-{task}-{YYYY.MM}.{patch}
例如：lessonplan-sft-2026.09.0
```

每个版本生成不可变 manifest，至少包含：

- 数据集 ID、任务类型、版本和创建时间；
- Schema 版本、筛选条件和候选时间范围；
- 去标识化规则、版权策略和变换代码版本；
- 样本数及学科、年级、教材版本、来源类型分布；
- 精确/语义去重参数；
- `train`、`validation`、`test` 成员清单和哈希；
- 固定黄金评测集排除清单；
- 每个样本的授权、许可、质量和来源血缘；
- manifest 的 SHA-256；
- 审核人和冻结时间。

拆分规则：

- 同一项目的所有修订必须在同一 split；
- 同一教材章节或高度相似内容必须通过 `split_group_key` 进入同一 split；
- 同一用户/机构的风格化内容尽量避免跨训练与测试泄漏；
- 黄金评测集永久排除；
- 撤权时根据样本血缘定位受影响数据集和模型版本。

## 12. 分阶段模型路线

### 阶段 0：外部视觉/大模型 + 项目 RAG

- 完成 OCR、人审、结构化生成、引用、修订、导出和评测；
- 不训练自有模型；
- 建立模型适配器、任务路由和隐私策略；
- 形成真实基线和黄金评测集。

### 阶段 1：数据治理和管理员素材库

- 建立授权、去标识化、版权、质量和人工审核流程；
- 管理员上传高质量教材、教案、习题和答案；
- 只把获得许可的内容放入对应范围的 RAG；
- 冻结第一批 SFT 数据集。

### 阶段 2：SFT

训练目标：稳定输出教案 Schema、学会教学流程和学科表达。训练数据优先级：

1. 专家复核且授权明确的管理员教案；
2. 用户明确授权、去标识化、质量达标并最终接受的教案；
3. 经专家审核的合成数据。

SFT 不负责记住全部教材原文；模型输入仍通过 RAG 提供章节内容。训练前后必须在同一黄金集上比较，防止格式提升但事实、习题或安全退化。

### 阶段 3：DPO

DPO 只采用：

- 用户明确选择 A 优于 B；
- 用户明确拒绝某修订并接受另一修订；
- 两位及以上专家按统一量表完成的成对比较。

不得将任意“旧版本/新版本”自动转成 rejected/chosen。DPO 主要优化详略、课堂语言、互动方式和修改指令遵从，教材事实仍由 RAG 提供。

### 阶段 4：蒸馏

1. 用强教师模型针对已授权输入生成多个候选；
2. 运行硬规则、学科验证、模型评分和人工抽检；
3. 只选择高质量最终输出作为学生模型标签；
4. 记录教师模型、提示词、采样参数、候选分数、选择方式和服务商条款核验；
5. 只存最终答案及必要的简短、可公开教学依据，不采集隐藏思维链；
6. 做版权长文本重合检测，避免学生模型复现教材原文。

蒸馏前必须确认基座模型许可证和教师模型服务条款允许目标用途。

### 阶段 5：自托管混合路由

不建议从零训练基础模型。优先选择许可适合商用的基座，以 LoRA/QLoRA 等方式训练教案规划与修订能力。低置信、复杂视觉和专业学科校验可继续回退到强模型。

路由可按质量和成本分层：

1. 自有模型生成；
2. 自动质量检查；
3. 低分任务调用强模型重试；
4. 两者都低分时交给用户确认或人工处理。

## 13. 训练运行、评测、灰度和回滚

每次训练运行必须冻结以下内容：

- 基座模型 ID、版本和许可证；
- 数据集 ID、版本和 manifest 哈希；
- 训练代码/镜像版本、随机种子和超参数；
- 训练方式 `SFT | DPO | DISTILLATION`；
- 计算环境、开始/结束时间、费用和日志；
- 输出模型哈希和安全扫描结果。

发布前评测至少包括：

- JSON Schema 通过率；
- 习题数与答案完整率；
- 来源忠实度和幻觉率；
- 时间线正确率；
- 各学科答案正确率；
- 教师盲评；
- 隐私、安全、偏见和提示注入测试；
- 延迟、吞吐和成本；
- 与当前生产模型的逐项回归差异。

任何硬门槛下降都禁止发布。灰度建议 `5% -> 20% -> 50% -> 100%`，每阶段观察足够请求量和至少一个完整业务周期。流量分配按稳定哈希完成，避免同一项目在修订过程中频繁切换模型。

回滚触发条件示例：

- Schema 失败率、生成失败率或 P95 延迟超过阈值；
- 习题答案正确率或教师评分显著下降；
- 出现隐私、版权、安全或跨租户事件；
- 成本超出预算；
- 管理员人工暂停。

回滚只修改在线路由，不删除训练运行和模型产物；保留证据用于复盘。修复后必须创建新的模型版本，禁止原地替换同名产物。

## 14. 管理员上传素材

后台上传向导应支持：教材、章节、优秀教案、习题集、答案、评分标准和课堂活动模板。流程：

```text
上传
  -> 安全扫描
  -> 权利与许可填写
  -> OCR/结构化
  -> 人工校对
  -> 去标识化
  -> 学科质量审核
  -> 选择用途（RAG/SFT/DPO/蒸馏）
  -> 发布到候选池或素材库
```

习题上传必须把题干、答案、解析、难度、知识点和来源拆分为结构化字段。教案上传应转换为 `lesson-plan.schema.json`，转换失败或重要字段缺失时进入人工编辑，不允许把任意文档直接标记为高质量训练样本。

管理员必须能查看：

- 素材授权范围和到期时间；
- OCR 差异及人工修改；
- 去标识化命中；
- 版权和质量审核记录；
- 已进入的数据集和训练运行；
- 受撤权或下架影响的模型发布。

## 15. 最小持久化对象

实现时至少需要以下逻辑实体：

- `teaching_projects`
- `source_assets`
- `ocr_pages` / `source_chunks`
- `generation_jobs` / `model_runs`
- `lesson_plans` / `lesson_plan_revisions`
- `change_requests` / `exports`
- `consent_events` / `rights_records`
- `quality_results`
- `training_candidates`
- `dataset_versions` / `dataset_items`
- `training_runs` / `evaluation_runs`
- `model_artifacts` / `model_releases`

所有可变业务对象使用乐观锁或版本号；教案修订、数据集版本、模型产物和授权事件均采用追加式记录，不覆盖历史证据。

## 16. 验收清单

- [ ] 三份 JSON Schema 均可被 JSON 解析器读取，并通过 Draft 2020-12 Schema 校验器自检。
- [ ] 教案少于 10 道习题时校验失败。
- [ ] 缺少习题答案、解析、难度或知识点时校验失败。
- [ ] 生成与修订有独立任务和状态记录。
- [ ] 用户能查看、接受、拒绝、恢复和导出指定修订版。
- [ ] 服务处理、原图训练、OCR 训练、最终教案训练和偏好训练授权相互独立。
- [ ] 未通过版权、隐私或质量审核的样本无法进入冻结数据集。
- [ ] 同项目、同章节近似样本不会跨 train/test 泄漏。
- [ ] 每个模型发布可追溯到数据集、训练运行、评测和审批人。
- [ ] 灰度期间可一键暂停和回滚到上一稳定版本。
- [ ] 管理员上传素材具有许可范围、到期和下架血缘。
